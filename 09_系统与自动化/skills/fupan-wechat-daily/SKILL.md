# 符攀店长·微信日常

## 用途与执行位置

面向顾客的个人微信朋友圈、普通微信群，使用真实门店素材。本文件是该技能口吻和流程的唯一规则来源。以下业务文件路径相对于「烧鸟店超级管理员」仓库根目录；不要把老板 Mac 的绝对路径用于同事电脑。

账号属于同事时，在账号主人授权的设备和账号上执行，不要求把他的私人微信长期登录老板电脑。老板侧可以制作发布包，再交给同事手机人工发布，或交给同事电脑上的本地执行器。生成发布包不等于已传输给同事；没有连接到目标电脑的执行工具时，不声称能远程控制。不得将老板本次账号或发送授权固化为其他账号的长期授权。

| 平台/渠道 | 已验证范围 | 执行要求 |
|---|---|---|
| Mac 个人朋友圈 | 2026-10-13，微信 4.1.1：选图、中文正文、仅自己可见、发表和相册回读完整成功一次，无人工补点 | CUA 菜单/选图/粘贴与原生鼠标事件结合；每次重新定位并验证 |
| Windows 个人朋友圈 | 尚未实测，尚无 Windows 执行脚本 | 复用内容规则，在同事授权的 Windows 设备重新验证控制、选图、隐私和发表 |
| 普通微信群 | 本次未测试 | 核对指定群与发送授权，独立测试；不从朋友圈结果推断群发成功 |

没有已授权的定时发送安排。一次成功不证明无人值守、锁屏执行、升级兼容或长期稳定。

## 内容与正式来源

优先使用本轮提供的图片、视频、语音、文字。至少有一个可核实的门店事实，配图须实际看过；视频按需要看片段及听对白。人物无法确认授权时改用食物、环境或不可识别人物的素材。

| `02_项目与事项/符攀 2026-第四季度事项表.md` | 私域目标、反馈和到店线索；计划不作为完成证据 |
| `08_品牌与店铺资料/01_店铺事实/店铺事实总表.md` | 店名、地址、营业时间、活动等确认口径 |
| `04_门店运营/02_菜单管理/` | 菜品、价格、售卖状态；待复核字段不对外使用 |

拍摄日期不从上传日期或文件名推定。旧照片可作一般介绍，不写成今天拍摄；不根据图片编造天气、库存、营业安排、客满或顾客评价。缺失事实则省略或询问，不把占位符发出去。

默认店长第一人称自然口吻：一个具体细节、一个核心看点、一个自然邀请。朋友圈通常 40—100 字，群消息通常 20—60 字；少表情、无模板化网红腔，不虚构个人经历。尚无符攀真实文案样本，不能声称复刻本人。账号身份和叙述身份应一致或经本人明确认可。

## 发布包、授权与结果

1. 核对日期、账号、渠道、素材事实和本次可见范围。默认准备朋友圈及群文案；明确仅测试一个渠道时，只做该渠道。
2. 同日查重，输出可审阅发布包。路径 `output/符攀微信日常/YYYY-MM-DD/序号/发布包.md`，序号递增，同条修改原包。包含正文、素材位置和顺序、事实依据、账号、渠道、范围、授权及状态。原件只读，不放账号凭据或顾客私聊。
3. 按仓库 AGENTS.md 和本轮有效授权执行。制作草稿不等于获准发表；已有明确授权则继续，不重复询问。新账号、群或可见范围不从旧记录继承。普通群、个人朋友圈、企业微信群和公众号不能相互替代。
4. 发送前截图核对正文、图片数量、提醒对象及范围。私密任务必须先看到“仅自己可见”选中，再确认编辑器显示“私密”；只有文案写“仅自己可见”不算设置成功。
5. 保存“发送中”，仅点击一次发表。回读匹配正文、素材、无失败提示；私密朋友圈还须核对锁标记。记录“界面已核实”，不宣称顾客已收到或阅读。
6. 结果不明时先查询，无法查清则记“发送结果待核实”并停止重发。不得以按钮点击、编辑器关闭或工具无报错替代回读。

唯一台账 `output/符攀微信日常/微信日常台账.md`，表格列：日期、发布包、主题、渠道、状态、核实方式、下一步。状态为草稿／待确认发送／渠道待接通／发送中／界面已核实／失败／发送结果待核实。人工补点须注明，不能算全自动。测试记录、截图和原图默认留本地，不把含第三方信息的屏幕截图提交仓库。

## Mac 执行与原生点击

优先用当前可用的 Computer Use 工具。原生鼠标回退只能在当前环境规则允许且用户授权该方式时使用；本技能不扩大工具权限。2026-10-13 用户明确要求改用其他点击方法后，原生事件实测成功。

1. 选择实际微信应用；本次 bundle ID 为 `com.tencent.xinWeChat`。用最新界面核对账号。菜单“窗口 → 朋友圈”可用；相机在截图中定位。
2. 本地选图使用文件选择器：Command+Shift+G、设置完整路径、回车，核对选中文件及可用的“打开”。返回编辑器核对缩略图。不要全选素材目录。
3. 编辑器初始正文焦点下粘贴中文，截图回读。没有焦点证据时先定位；不盲目覆盖已有草稿。
4. “提醒谁看”默认不选。仅操作明确指定且授权的对象；录制中的搜索词不是授权名单。
5. CUA 原生菜单和文件选择器可点击，但微信内部相机、隐私及发表按钮曾返回 `AXError.notImplemented`。同一方法反复失败时不让用户重录；记录问题，使用获准的原生鼠标回退。

### 窗口和坐标

`scripts/mac_wechat_click.py` 仅提供可检查的单次左键事件，不负责选择账号、理解按钮或决定发表。使用 Python 标准库 `ctypes` 调用系统 CoreGraphics；不需要下载鼠标工具。无参数执行显示用法，`--list-windows` 只读列出微信可见窗口及边界。

先用 CUA 获取当前目标窗口完整截图，再读取窗口列表，以标题、尺寸、层级对应到该窗口 ID。原生窗口列表可看见辅助功能树漏掉的隐私弹窗。截图如果只包含表单，必须匹配表单窗口，不能套用父窗口位置。没有唯一对应关系就停止点击，重新观察。

坐标按当前截图尺寸换算为屏幕逻辑坐标：`screen_x = window_x + image_x * window_width / image_width`，Y 同理。本次截图像素为窗口逻辑尺寸的两倍；不得将“两倍”作为所有设备的固定值。多屏坐标可为负数。截图被裁切或包含多个窗口时，不能直接套用此公式。

将换算结果及刚观察到的窗口边界传入脚本；默认仅预览，`--execute` 才点击。参数 `--bounds` 顺序是 X Y Width Height。运行前避免用户同时移动窗口；脚本在激活后再次检查窗口位置、尺寸和层级，但不能替代截图核对按钮。

```text
python3 scripts/mac_wechat_click.py --list-windows
python3 scripts/mac_wechat_click.py --window-id ID --bounds X Y WIDTH HEIGHT --point SCREEN_X SCREEN_Y
```

确认预览对应正确窗口和按钮后，使用相同参数加 `--execute`。每次点击后用 CUA 获取新的状态和截图，重新定位下一步。权限不足时报告缺口，不自动修改系统权限。辅助功能授权成功或事件发送成功均不等于按钮操作成功。

## Windows 适配边界

同事私人号应在同事自己的 Windows 设备上授权执行。把素材路径转换为该电脑真实可读位置，再核对账号、微信版本、窗口位置、显示缩放和桌面是否可交互。Mac 的 CGEvent 脚本不能在 Windows 运行。

有 Windows 电脑控制工具时，优先按实际控件/截图操作；没有则交付发布包，状态为“渠道待接通”。下一步验收是经账号主人同意，用一条明确标记的测试内容完成选图、文案、私密、发表和相册回读。未在该机验证前，不宣称 Windows 已兼容或已部署。

wxauto 是可选的第三方 Windows 工具，不是必需依赖。2026-10-13 查阅官方文档，`PublishMoment` 标为 Plus 专用，免费版不能直接调用该发布接口；使用前重新核实客户端兼容、功能和授权，不自动购买。来源：[安装与版本](https://docs.wxauto.org/docs/install.html)、[朋友圈接口](https://docs.wxauto.org/docs/class/WeChat.html)。
