# `$uploader` OSS 素材库使用说明

## 用途

`$uploader` 是本项目专用的阿里云 OSS 素材库工具，用来完成四件事：

1. 查看 OSS 里有哪些素材。
2. 识别本地目录中已上传和未上传的素材。
3. 对新素材进行内容分类，确认后幂等上传。
4. 将 OSS 素材按正式分类下载到指定目录。

它使用阿里云 OSS 原生 SDK，不使用 AWS CLI。

## 最简单的用法

直接在 Codex 中说明要做什么，无需自己运行脚本。

| 目的 | 可以直接说 |
| --- | --- |
| 查看整个素材库 | `$uploader 看看 OSS 素材库里有什么` |
| 查看指定分类 | `$uploader 列出“烧烤食材展示”里的素材` |
| 搜索素材 | `$uploader 找名字或路径里有“湖边”的素材` |
| 处理并上传目录 | `$uploader 处理这个文件夹：/绝对/路径，把新素材分类并上传到 OSS` |
| 下载全部素材 | `$uploader 把 OSS 素材库下载到 /绝对/目标目录` |
| 增加新分类 | `$uploader 增加分类“人物故事”，识别关键词是老板、员工、采访、人物` |

## 现有内容分类

- 店内环境宣传
- 后湖湖边茶饮
- 后湖落日湖景
- 烧烤成品特写
- 烧烤烤制过程
- 烧烤食材展示
- 同行参考（保留出处，仅供研究，不作为自家发布素材）
- 其他待判断

一般内容分类描述素材拍了什么；老板新增的“Live图”按配对成品类型归类，两个配对资源不能拆分到不同菜品类别。无法确定的新素材放入“其他待判断”，不硬猜。

## 上传一个素材目录

给出的目录可以是全部上传过、部分上传过，或全部未上传。`$uploader` 会递归扫描支持的图片、视频和音频，然后对每个文件计算 SHA-256。

处理顺序：

1. 用文件内容的 SHA-256 查询 OSS，不用文件名或本地路径判断。
2. 已上传素材直接沿用 OSS 中的正式分类，不重传、不重新分类。
3. 只对新素材分类：查看图片，并为视频抽取代表帧后判断内容。
4. 生成上传计划，汇报总数、已存在数、待上传数和分类统计。
5. 用户确认上传后，才真正写入 OSS。
6. 上传后再扫描验收，确认新文件均已被 OSS 索引识别。

相同文件改名、换目录或重复执行，都不会重复存储。

## 查看和搜索

查看整体素材库时，默认返回：

- 唯一素材数。
- 总容量。
- 上传批次数。
- 每个分类的素材数和容量。

按分类或关键词查询时，还会列出文件名、相对路径和大小。查看操作是只读的，不会下载、修改或删除 OSS 对象。

## 下载素材

下载整个素材库时，需要明确说“全部”或给出“素材库”整体范围。下载结果的实际结构是：

```text
<目标目录>/
└── <内容分类>/
    └── <拍摄日期>/
        └── <批次主题>/
            └── <原相对路径>/
```

下载具有以下保护：

- 本地已有且 SHA-256 相同：跳过。
- 本地同名但内容不同：保留本地文件，远程文件另存为 `.remote-<hash>` 版本。
- 下载完成后再校验 SHA-256；校验失败的文件不保留。
- 下载不会删除或修改 OSS 上的素材。

默认拉取本机未见过的批次；一台新电脑首次默认只拉最近 3 个批次。需要完整素材库时使用全量下载。

## 增加内容分类

增加分类时，同时给出分类名和常见内容特征或关键词。新分类会进入分类校验、自动提示和库内查询条件。

新分类只影响之后扫描的新素材，不会自动改变 OSS 中旧素材的正式分类。如果要整理旧素材，需要先生成重分类变更清单，经用户确认后再修改 OSS 索引。

## 命令行参考

日常使用不需要自己执行命令。如需排查，在项目根目录中使用已安装 `oss2` 的 Python 环境：

```bash
# 查看总量与分类统计
.venv/bin/python 09_系统与自动化/skills/uploader/scripts/oss_materials.py inventory

# 按分类查看
.venv/bin/python 09_系统与自动化/skills/uploader/scripts/oss_materials.py inventory --category "烧烤食材展示"

# 按关键词搜索
.venv/bin/python 09_系统与自动化/skills/uploader/scripts/oss_materials.py inventory --search "湖边"

# 扫描本地目录，只生成计划
.venv/bin/python 09_系统与自动化/skills/uploader/scripts/oss_materials.py scan --source "/绝对/素材目录" --topic "批次主题"

# 上传预览，不写入 OSS
.venv/bin/python 09_系统与自动化/skills/uploader/scripts/oss_materials.py upload --plan "/绝对/上传计划.json"

# 确认后真正上传
.venv/bin/python 09_系统与自动化/skills/uploader/scripts/oss_materials.py upload --plan "/绝对/上传计划.json" --execute

# 下载所有批次
.venv/bin/python 09_系统与自动化/skills/uploader/scripts/oss_materials.py pull --destination "/绝对/目标目录" --all
```

## 配置与安全

本机需要配置：`OSS_ACCESS_KEY_ID`、`OSS_ACCESS_KEY_SECRET`、`OSS_BUCKET` 和 `OSS_ENDPOINT`。`OSS_PREFIX` 可选，默认为 `material-library/v1`。

配置保存在被 Git 忽略的项目根目录 `.env` 或本机密钥管理中。不得将 AK/SK、Token 或其他云存储凭据写入文档、日志、上传清单或 Git。

安全规则：

- 上传必须经用户明确确认。
- 查看和下载不会改动远程数据。
- 不自动删除或覆盖 OSS 原始素材。
- 远程已有分类与本次计划冲突时立即停止，不自动覆盖。

## 常见问题

### 重复给同一个目录，会重复上传吗？

不会。是否重复由文件内容的 SHA-256 判断，与名称和路径无关。

### 每次都要扫描本地吗？

只有处理一个本地上传目录时需要扫描。查看 OSS 库存不扫描本地；下载依据远程批次和本地同步状态处理。

### 图片或视频改名后会被当成新素材吗？

不会。只要文件内容没变，SHA-256 就相同。

### 谁才是分类的正式来源？

OSS `catalog/<hash>.json` 中的分类是唯一正式来源。本地计划只处理新素材，不覆盖已有远程分类。

### 下载到已有文件的目录会怎样？

内容相同的文件会跳过；同名但内容不同时，两份都保留，不覆盖本地文件。

## Live图类别

已加入`Live图`，可用`inventory --category "Live图"`查询。来源为顶层`素材库/Live图/`，新文件目录提示优先归此类，仍需审核并核实配对后上传。一个Live含JPG和MOV两个媒体对象，库存文件数不是Live组数。MP4预览与验收图不能当作额外Live组。整组保留相对路径，避免跨版本配错；旧hash分类不变。当前上传器不处理JSON来源文件，本地素材信息不会自动上传。
