# 冰箱账号运营：安装与使用说明

## 这是什么，当前能做到哪一步

这是交给 Codex 执行的冰箱账号工作说明，需要在 Codex 中使用，不是双击运行的软件。规则只在[SKILL.md](SKILL.md) 中维护，本页负责安装与使用。

| 能力 | 当前状态 |
|---|---|
| 小红书选图、文案和预览 | 已定义流程，由 Codex 结合本地素材执行 |
| 图片轻修 | 需要当前环境的图像处理工具；先出样张并对照原图 |
| 已发布照片检查 | 根据发布记录、原图摘要及画面对比；历史记录缺失时无法保证完全去重 |
| 小红书实际发布 | 有可用的平台操作工具、账号与地点核对完成且当前版本获确认后才能执行；本 Skill 不自带发布程序 |
| 抖音运营与自动发布 | 待扩展，尚未接通 |
| 每天定时运行 | 未配置；文档里的发布时间只是计划，不会自动唤醒执行 |

## 安装与更新

适用于本项目的 macOS + Codex 环境。需要先安装 [Codex](https://developers.openai.com/codex/app/)，并把私有仓库 [yakitori-store-admin](https://github.com/xiaokeke49/yakitori-store-admin) 克隆或拉取到本机。协作者需要仓库访问权限。该 Skill 的安装本身不需要 Python、Node、API Key 或 `pip install`。

1. 在 Codex 中打开本仓库。
2. 在仓库根目录打开终端，执行下方命令。第一条检查应显示 `SKILL.md` 路径；若不存在，先检查当前位置和仓库版本。
3. 安装后，在下一轮对话调用 `$fridge-account`。

```sh
ls "09_系统与自动化/skills/fridge-account/SKILL.md"
mkdir -p "${CODEX_HOME:-$HOME/.codex}/skills"
ln -s "$PWD/09_系统与自动化/skills/fridge-account" "${CODEX_HOME:-$HOME/.codex}/skills/fridge-account"
```

目录关系如下：

```text
仓库/09_系统与自动化/skills/fridge-account/SKILL.md  ← 唯一正式文件
本机 ~/.codex/skills/fridge-account/               → 指向仓库目录的软链接
```

如果设置了 `CODEX_HOME`，本机安装位置相应为其下的 `skills/fridge-account`。每位协作者各自在自己的电脑安装一次；软链接不会随 Git 分享到其他电脑。

## 如何确认安装成功

在终端执行：

```sh
readlink "${CODEX_HOME:-$HOME/.codex}/skills/fridge-account"
test -f "${CODEX_HOME:-$HOME/.codex}/skills/fridge-account/SKILL.md" && echo "Skill 文件可读取"
```

第一条应显示当前仓库中的技能目录，第二条应显示“Skill 文件可读取”。接着在 Codex 下一轮对话发送：

```text
$fridge-account 先检查这个 Skill 是否可读取，并说明当前支持哪些平台，不制作或发布内容。
```

## 第一次使用前准备什么

| 资料或条件 | 如何提供 | 缺少时怎么处理 |
|---|---|---|
| 原始照片 | 上传附件或给出本机文件夹完整路径 | 没有素材无法制作真实图文 |
| 拍摄日期 | 标注当天或历史素材；不同日期分开说明 | 无法确认时按历史素材处理 |
| 商品信息 | 已知名称、价格依据、库存和当天经营例外 | 不猜测，可先做不含价格的预览 |
| 历史发布记录 | 提供现有记录或已发布作品链接 | 标注去重未完全核实，实际发布前补齐 |
| 平台操作条件 | 实际发布前由你完成所需登录，并核对账号和地点 | 可以先做预览，无法核对时不发布 |

不要把密码、验证码、Cookie 或 Token 写进仓库或聊天。账号和门店的固定口径查看 Skill 中的“固定经营资料”，有变化直接说明。

## 日常怎么用

直接复制下面的话，把方括号部分换成真实信息：

```text
$fridge-account 帮冰箱账号制作一版小红书预览，先不发布。
素材文件夹：[本机照片文件夹完整路径]
拍摄日期：[日期；不清楚就写不清楚]
商品信息：[已确认的商品名称；不清楚就注明]
价格依据：[价目表路径或本次不写价格]
库存及当天经营例外：[已确认信息或未知]
历史发布记录：[记录路径/作品链接/暂无记录]
不能出现的内容：[没有或具体说明]
希望发布时间：[时间或按 Skill 默认]
```

| 场景 | 可以直接这样说 |
|---|---|
| 只检查素材 | `$fridge-account 检查这批照片是否够用、是否可能重复，先不修图。` |
| 调整预览 | `$fridge-account 把刚才那版文案改得更像老板日常，给我新版本预览。` |
| 发布已确认版本 | `$fridge-account 确认发布小红书预览 [日期/版本]，先核对账号和地点。` |
| 已自行发布 | `$fridge-account 我已手动发布 [版本]，链接是 [作品链接]，请核实并补齐发布记录。` |

只确认图片不等于确认整篇发布。图片、文案、账号或地点变化后，要重新确认版本。若当前没有平台操作工具，Codex 应交付可手动上传的文件并说明未发布；不会因为回复“确认发布”就假定发布成功。

## 会收到什么，保存在哪里

先收到图片样张或完整预览，包括全部图片顺序、首图理由、标题、正文、话题、待确认信息、素材去重结果、预计时间及账号和地点核对结果。未核实的项目会明确标记。

| 内容 | 相对于仓库根目录的位置 |
|---|---|
| 操作规则 | `09_系统与自动化/skills/fridge-account/SKILL.md` |
| 安装和使用说明 | `09_系统与自动化/skills/fridge-account/使用说明.md`（本文件） |
| 小红书预览及处理后的图片 | `06_公域运营/产品展示冰箱/小红书发布预览/YYYY-MM-DD/` |
| 成功发布记录 | `06_公域运营/产品展示冰箱/小红书发布记录.md`，首次实际成功发布时建立 |
| 原图 | 保留在原位置，不覆盖 |

同日多版使用版本号；已确认或已发布的版本不覆盖。发布记录应包含时间、作品链接、版本、原图路径与 SHA-256 等信息。上述产物路径是约定，不表示文件已经生成。

## 更新、卸载和常见问题

在 GitHub Desktop 中拉取仓库最新内容即可更新规则；软链接不需要重复安装。自己修改规则时只编辑仓库中的 `SKILL.md`，不要另存本机副本。遇到 Git 冲突先解决冲突，再继续使用。

| 问题 | 处理方法 |
|---|---|
| 安装提示 `File exists` | 先运行 `readlink`。如果已经指向本仓库且文件可读取，就是已安装；若是其他目录或普通文件，先检查并备份，不要强制覆盖 |
| 提示找不到 `SKILL.md` | 确认终端在仓库根目录，且已拉到包含该 Skill 的版本 |
| 安装后没有识别 | 先验证软链接和文件可读，再发起下一轮对话；仍未识别可直接附上仓库 `SKILL.md` 请 Codex 读取，并检查安装目录是否对应当前 Codex 环境 |
| 仓库换了位置 | 原链接可能失效；按下面方式移除旧链接，再在新仓库根目录重新安装 |
| 能写文案却不能发布 | Skill 规则已加载不代表平台工具已接通；需要补齐当前环境的操作工具、登录及账号地点核对 |
| 到时间没有自动发 | 当前没有定时任务和完整自动发布程序，需要另外配置 |

卸载时只移除本机安装链接，仓库文件、原图和发布记录保留。确认要卸载后运行：

```sh
if [ -L "${CODEX_HOME:-$HOME/.codex}/skills/fridge-account" ]; then
  unlink "${CODEX_HOME:-$HOME/.codex}/skills/fridge-account"
else
  echo "该位置不是软链接，未删除，请先检查。"
fi
```

重新安装使用上面的安装命令即可。
